1 # Correcting Data
2 ## Removing dumped GRIF-16 events <a name="bufferclear" />
3 The GRIF-16's add extraneous events to the start of every run. To remove these, the **bufferclean** utility can be used. This script looks for the first time a digitizer has a Channel Trigger Id < some threshold and removes all events from this digitizer that come before that. The threshold is currently set to 50. To use **bufferclean** type:
4 ```
5 bufferclean name_of_midas_file.mid name_of_output.mid
6 ```
7 The output midas file should have the events properly cleared.

9 ## Fixing GRIF-16 Timestamp Offsets <a name="offsetfix" />
10 Sometimes, the GRIF-16 digitizers do not properly reset their timestamps at the start of a new run. To fix the timestamps, you must first make sure you have cleaned out the [extra buffer events](#bufferclear) at the start of the Midas File. The fix the offsets, use **offsetfix**.
11 ```
12 offsetfix name_of_midas_file.mid name_of_output.mid
13 ```
14 The script works by using the [offsetfind](#offsetfind) algorithm, and shifting all of the timestamps by the found time shifts. It then outputs a corrected Midas file. To check that the finding script found the correct timestamp shift, you can look at **time_diffs*runnumber*.root**. The histograms labeled *timediff* are the final peak found after employing the [offsetfind](#offsetfind) algorithm. It should be noted that this also shifts the current offset between 4G's and GRIF-16's from their current 800 ns shift to 0 ns.

16 ## Finding GRIF-16 Timestamp Offsets <a name="offsetfind" />
17 Sometimes, the GRIF-16 digitizers do not properly reset their timestamps at the start of a new run. To find the timestamp offset from each address, the **offsetfind** algorithm can be used. This is a script in it's own right, but is mostly useful for checking that the [offsetfix](#offsetfix) script worked properly.
18 #### The way it works
19 1. The first thing the script does is look for the smallest high time stamp of all of the GRIF-16's, this becomes the *reference GRIF-16 digitizer*.
20 2. All of the high timestamps for a specific digitizer are then shifted by the smallest high timestamp for that specific digitizer.
21 3. The total timestamp of an event for each digitizer is then compared to the the total timestamp for the *reference digitizer*. This is plotted for each digitizer on a TH1 called rough_*address* that contains enough bins to encompass an entire high time stamp worth of bins. This is "rough" offset finding as we can only accept a certain number of events due to the size of the plot.
22 4. Finally, this "rough" offset is applied and we repeat step 3 on a more fine-tuned scale. The largest bin in the time difference plot is found, and the final shift is based on this amount. The final plot used is contained in the spectrum timediff_*address*. <br>
23 The code outputs the timestamp offset it has currently found for each digitizer at each step in the process.
