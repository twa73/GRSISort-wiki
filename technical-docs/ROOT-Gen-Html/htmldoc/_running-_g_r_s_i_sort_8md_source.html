15 <a name="unpackmid" />
16 # Unpacking the MIDAS File
17 The strategy used by GRSISort is to unpack the MIDAS file and convert the information into a ROOT Tree format. This tree contains <a href="https://rawgit.com/wiki/r3dunlop/GRSISort/technical-docs/ROOT-Gen-Html/htmldoc/TFragment.html# TFragment:Data_Members" target="_blank">TFragments</a> and is essentially all of the information from the MIDAS File with higher compression and accessibility.
18 
19 **grsisort NAME_OF_MIDAS_FILE.mid** -> Converts the midas file into a fragment tree
20 
21 Some currently accepted flags for the midas sort:
22  * __--suppress_error__, suppresses errors from failed data parsing appearing in stdout
23  * __--log_errors__, sends errors from failed data parsing to file, will not send errors if supress error option is also used!
24  * __-q__, quits the grsi environment after completing the midas sort (important when sorting a file)
25  * __-b__, run in batch mode (useful when running a ```<macro>.C`` script on the sorted file
26 
27 Only one midas file can be sorted at a time.
28 <a name="sortfrags" />
29 # Sorting the Fragment Tree
30 **grsisort [-a -H] NAME_OF_FRAGMENT_TREE.root** -> Starts sorting the fragment tree into (-s) user defined hists and/or (-a) analysis trees.
31  * Histograms are defined in **users/UserInitObj.h**
32  * How to fill the histogram is defined in **users/UserFillObj.h**
33 
34 If **-a** or **-H** are left off of the command, the fragment tree will be loaded into the grsi environment for the user to enjoy.
35 
36 Some currently accepted flags for the fragment tree sort:
37  * __-a__, creates an analysis tree to be used for doing a full analysis of the data
38  * __-H__, sorts the fragment tree into user defined hists
39  * __-q__, quits the grsi environment after completeing the fragment sort
40 
41 For more information about available flags run ```grsisort -h```.
42 ## Calibrating the gamma spectra
43 When sorting the fragment tree, you can read in a [calibration file](CalFiles) at the same time and it will perform the calibrations while sorting. This can be done with the command:
44 ```c++
45 grsisort -flags <midasfile>.mid <calibrationfile>.cal
46 ```
47 If a different calibration is supposed to be used it can be either loaded temporarily by giving the corresponding .cal file after the fragment/analysis tree file, or it can be written permanently to the files by using the **WriteCalToRoot** program which can be used to update or replace the calibration.
48 It is possible to use multiple calibration files, in which case for duplicate entries the value will be taken from last file provided. This can be used e.g. to provide energy calibrations and cross-talk corrections is separate files.

50 ## Displaying parameters of fragment tree
51 You can list the parameters included in the fragment tree with:
52 ```c++
53 FragmentTree->Print()
54 ```
55 
56 Alternatively, you view them in a graphical interface with:
57 ```c++
58 FragmentTree->StartViewer()
59 ```

61 ## Viewing histograms within `grsisort`
62 After sorting the data and creating a fragment tree, you can create histograms by running normal ROOT commands:
63 ```c++
64 FragmentTree->Draw("<variable> >> <histogramName>(<xbins>,<xmin>,<xmax>)", "<cuts>", "<displayOptions>")
65 ```
66 
67 Here is an example that displays a 1D histogram of calibrated energy of all detectors:
68 ```c++
69 FragmentTree->Draw("GetEnergy() >> h(16000,0,16000)", "", "")
70 ```
71 
72 Another example, of a 2D histogram that displays calibrated energy vs. detector number ignoring channel 12, is:
73 ```c++
74 FragmentTree->Draw("fChannelNumber:GetEnergy() >> h(16000,0,16000,64,0,64)", "fChannelNumber!=12", "LEGO")
75 ```

77 #### The Autosort Feature
78 If the __-a__ flag is used on the MIDAS file, GRSISort will sort the MIDAS file and complete a fragment sort by applying the flags and sorting the fragment tree, making an analysis tree file.
