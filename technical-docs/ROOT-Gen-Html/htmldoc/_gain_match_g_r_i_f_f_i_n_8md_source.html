1 ## Scope
2 The GainMatchGRIFFIN macro is designed to gain-match GRIFFIN detectors relative to each other, not a specified energy calibration. It has been designed as a sequential execution of many [smaller functions](#smaller-functions) that will take the user from initial data set to calibration file and diagnostic images to evaluate the quality of the gain match.
3 
4 It is important to note that this is a *gain-matching* code, not an energy calibration code. Slopes and offsets are applied to each crystal so that its peaks will line up with the peaks in the crystal with the lowest channel number. A *rough*, linear, energy calibration may also be applied.
5 
6 ## Usage
7 A set of [variables](#variables) should be set for each gain-matching. Then `GainMatchGRIFFIN.C` should be (re)compiled. The compilation line is given in the commented first line of the file. Once it has been compiled, the user may gain match a run by running:
8 
9  ./GainMatchGRIFFIN <fragment filename(s)>
10 
11 from the command line. The file name of the raw data (i.e. `fragmentXXXX_XXX.root`) is taken as input to the compiled function.
12 
13 ## Variables
14 The most commonly used variables are declared in the `main()` function at the bottom of `GainMatchGRIFFIN.C`. They in the section of code marked `//-------------- VARIABLE DECLARATION SECTION --------------//`. The variables that are hard-coded at the time of compilation are:
15 - `minchannel`: lowest GRIFFIN channel number for gain-matching.
16 - `maxchannel`: highest GRIFFIN channel number for gain-matching.
17 - `channelstoskip`: a vector of integers that lists channels that should not be gain-matched, but that are between `minchannel` and `maxchannel`.
18 - `xbins_charge`: the number of bins used in creating the raw charge histograms.
19 - `xmin_charge`: the minimum bound on the charge axis in the raw charge histograms.
20 - `xmax_charge`: the maximum bound on the charge axis in the raw charge histograms.
21 - `integration`: the integration parameter by which charge is divided before it is calibrated. This should ideally be set to the integration parameter of the GRIFFIN digitizers, which have a default of 512.
22 - `roughenergy`: set to `kTRUE` if a rough energy calibration is desired. set to `kFALSE` if not.
23 - `largepeak`: the value of the largest peak. If you use a rough energy calibration, this should be in keV. Otherwise, it may be in charge units.
24 - `fittingpeaks`: a vector of peaks used for fitting. While these values may be approximate, they should be in keV if a rough energy calibration is desired.
25 - `mindistance`: the +/- value that sets the search window when looking for peaks in the raw histograms. Should be in units of your raw histogram (most likely charge).
26 - `twopeaks`: a boolean variable that tells the code to expect two equally strong large peaks. To use, set to true and then declare `largepeak2`.
27 - `largepeak2`: if there are two nearly equally large peaks (say in <sup>60</sup>Co), set this value to the value of the second largest peak. If you use a rough energy calibration, this should be in keV. Otherwise, it may be in charge units.
28 - `calFile`: the name of your output calibration file.
29 - `xbins_energy`: the number of bins used in creating the calibrated energy histograms.
30 - `xmin_energy`: the minimum bound on the charge axis in the calibrated energy histograms.
31 - `xmax_energy`: the maximum bound on the charge axis in the calibrated energy histograms.
32 - `peakstocheck`: a list of peaks (again, in keV if you'd like a rough energy calibration) that will be checked to evaluate the quality of the fit. Does not have to be the same as the `fittingpeaks` vector, but may.
33 - `windowsize`: the +/- value that sets the search window when looking for peaks in the calibrated histograms. If you have requested a rough energy calibration, should be in keV.
34 - `do_make_calibration_histograms`, `do_create_gainmatch_graphs`, etc.: these Booleans turn on and off the [smaller functions](#smaller-functions) within the code. It is expected that the user will not want to execute all of the functions at all times. As an example, the histograms that are going to be used for calibration (raw "Charge" spectra) are likely to only be created once. If the inital gain-match is unsatisfactory, the user can set `do_make_calibration_histograms` to false and recompile the macros for faster running.

36 ## Output files
37 ### With a single fragment file
38 - `calib_<raw filename>`: This ROOT file contains the raw charge histograms for each channel that are created by the [`make_calibration_histograms`](#make_calibration_histograms) function. They are named `hst1`, `hst2`, etc. where the number is the channel number. After executing the [`create_gainmatch_graphs`](#create_gainmatch_graphs) function, it also contains energy vs. charge TGraphs for each of those histograms, with points for each of the peaks specified in the `fittingpeaks` array. If something goes wrong in the peak-finding, these TGraphs can be modified on a point-by-point basis before executing the [`create_GRIFFIN_cal`](#create_griffin_cal) function.
39 - `GRIFFINcal.cal`: (or whatever else you set the `calFile` variable to): This is the calibration file that is output from the [`create_GRIFFIN_cal`](#create_griffin_cal) function.
40 - `GRIFFIN_fitting_params.png`: This PNG diagnostic canvas shows the slopes, offset, and chi-square values from the linear fit of the graphs in the `calib_<raw filename>` file as a function of channel number.
41 - `GRIFFIN_calgraph.png`: This diagnostic canvas plots all the graphs in the `calib_<raw filename>` file on top of each other.
42 - `newcal_<raw filename>`: This ROOT file contains the calibrated energy histograms that are created by the [`recalibrate_spectra`](#recalibrate_spectra) function for each channel. Again, they are named `hst1`, `hst2`, etc. This file also contains a few diagnostic histograms:
43  - `hstall`: This is the sum of all available channel histograms.
44  - `residualXX`: These histograms show the difference between the peak centroids of a single crystal and the peak centroids of the summed spectrum.
45  - `fwhm`: This 2D histogram plots the FWHM for each crystal as a function of energy.
46  - `fwhmratio`: This 2D histogram plots the FWTM/FWHM ratio for each crystal as a function of energy.
47  - `fwhm_all`: This 2D histogram plots the FWHM for the summed spectrum (`hstall`) as a function of energy.
48  - `fwhmratio_all`: This 2D histogram plots the FWTM/FWHM ratio for the summed spectrum (hstall) as a function of energy.
49 - `GRIFFIN_FWHM_diagnostic.png`: This diagnostic canvas shows the histogram `fwhm` plotted as a [candle plot](#candle-plots) and the `fwhm_all` histogram plotted on top, with star points. If the gain-matching has been successful, the star will be within the solid outline box.
50 - `GRIFFIN_FWHMratio_diagnostic.png`: This diagnostic canvas shows the histogram fwhmratio plotted as a [candle plot](#candle-plots) and the fwhmratio_all histogram plotted on top, with star points. If the gain-matching has been successful, the star will be within the solid outline box.
51 
52 ### With multiple fragment files
53 It is occasionally useful to combine the counts from multiple subruns or runs before gain-matching (to use low-intensity peaks, for example.) This code has been set up to accomodate this. If the user lists multiple filenames in the command line call of GainMatchGRIFFIN, the output will differ slightly. All individual ROOT fragment files will have corresponding `calib_<raw filename>` and `newcal_<raw filename>` files. After these are created, however, `hadd` will be called to sum them into new ROOT files, respectively called `calib_hst_summed.root` and `newcal_summed.root`. The individual ROOT files will contain the charge and energy histograms listed above, but the TGraphs and the diagnostic histograms will exist on in the summed files.

55 ## Smaller functions
56 ###`make_calibration_histograms`
57 This function takes in the `FragmentTree` ROOT file and outputs a ROOT file containing histograms for all channels between `minchannel` and `maxchannel`, excluding those in the `channelstoskip` vector.
58 
59 ###`create_gainmatch_graphs`
60 This function finds peaks in the uncalibrated spectra and correlates them with calibrated values. It takes in the `calib_<raw filename>` ROOT file created in [`make_calibration_histograms`](#make_calibration_histograms) that contains the uncalibrated spectra and adds graphs to that file. Those graphs show the uncalibrated peak value vs. the calibrated peak value for an individual crystal. The calibrated values are NOT set to the values given by the user in the `fittingpeaks` vector, but are instead set to the values of the peaks found in the first spectrum - the histogram associated with channel number `minchannel`. If a rough energy calibration is selected, a linear calibration is applied to convert the calibrated charge values to roughly calibrated energy values.
61 
62 ###`create_GRIFFIN_cal`
63 This function takes in the graphs created in [`create_gainmatch_graphs`](#create_gainmatch_graphs), linearly fits them, and creates a calibration file that may later be used to calibrate GRIFFIN data. It also outputs two diagnostic images: an overlay of all the graphs used, with points colored to represent the color of the crystal they show (`GRIFFIN_calgraph.png`), and histograms showing the slope, offset, and chi-square of each linear fit (`GRIFFIN_fittingparams.png`).
64 
65 ###recalibrate_spectra
66 This function takes in the original data file and the newly created calibration file (`GRIFFINcal.cal`). It outputs a new ROOT file with calibrated histograms (`newcal_<raw filename>`).
67 
68 ###check_calibration
69 This function takes in the ROOT file with calibrated histograms that was created in the [`recalibrate_spectra`](#recalibrate_spectra) function (`newcal_<raw filename>`) and measures the FWHM and FWTM of the peaks listed in the `peakstocheck` vector. It also sums all the channels together and measures the FWHM and FWTM of that summed histogram. It then outputs two diagnostic images: one comparing the distribution of FWHM among all the crystals to the FWHM of the summed spectrum (`GRIFFIN_FWHM_diagnostic.png`) and another comparing the distribution of the FWTM/FWHM ratio among all the crystals to the FWTM/FWHM ratio of the summed spetrcum (`GRIFFIN_FWratio_diagnostic.png`), both using [candle plots](#candle-plots).
70 
71 ## Candle plots
72 Candle plots are made using the "candle" draw option in ROOT. The mean of the distribution is given with an open circle. The median is given by a solid horizontal line. The dashed line spans the full range of the data, from minimum to maximum values. The box shows the range of the middle 50% of the data; the limits are the first and third quartile lines. 25% of the data is outside and below the box, and 25% of the data is outside and above the box.

74 ## Troubleshooting
75 This code was not written to be a be-all, end-all gain-matcher. It will be necessary at times to modify the code for a particular set of data. If you have a "if your data look like this, you can make this change" suggestion, please add it here.
