3 # Commenting Code For HTML
4 The [TGRSIDetectorHit](https://rawgit.com/wiki/GriffinCollaboration/GRSISort/technical-docs/ROOT-Gen-Html/htmldoc/class_t_g_r_s_i_detector_hit.html ) class is a good example of how to comment a class for automatic HTML generation using doxygen. Please see the [doxygen](http://www.doxygen.org/index.html) page for more information about doxygen, and [doxygen & ROOT](https://dberzano.github.io/alice/doxygen/) for tips on using doxygen with ROOT.

6 ### Class Description
7 [[/images/ClassDesc.png]]
8 
9 To create the class description, place it in a block of comments such as:
10 ```c++
11 /////////////////////////////////////////////////////////////////
12 ///
13 /// \class TGRSIDetectorHit
14 ///
15 /// This is class that contains the basic info about detector
16 /// hits:
17 /// 1. An address. The whoami for the detector. This is the value used by TChannel::GetChannel(address);
18 ///
19 /// 2. An "Energy value." What this is left the parent class, but it is going to return a double.
20 ///
21 /// 3. A Time value. This should be a time value common for detectors (derived from the timestamp)
22 /// Units matter here, I am adobting the ns as the standard.
23 ///
24 /// 4. A Position. Tvector3s are nice, they make doing geometery trival. Each hit needs one to determine
25 /// where it is in space, the actual memory of the thing will be stored here.
26 /// *** This is not actually needed here unless we start do waveform analysis to
27 /// *** better determine where the hit is.
28 ///
29 /// 5. The waveform. Since we are dealing with digital daqs, a waveform is a fairly common thing to have. It
30 /// may not always be present, put it is echoed enough that the storage for it belongs here.
31 ///
32 /////////////////////////////////////////////////////////////////
33 ```
34 This block of comments should go in the header file, ie the .h file.

36 ### Class Index
37 [[images/ClassIndexDesc.png]]
38 
39 To add the class to a specific group (in this case Detectors), add the following three lines at the very top (right after the #ifndef and #define statements):
40 ```c++
41 /** \addtogroup Detectors
42  * @{
43  */
44 ```
45 and the closing bracket after the class description (just before the #endif):
46 ```c++
47 /*! @} */
48 ```

50 ### Method Documentation
51 [[images/FuncDesc.png]]
52 
53 To create method documentation, place the instructions or details in the first comments after the name of the function using ```///```. Everything until the first line without ```///``` is considered as a valid member function description block.
54 For example,
55 ```c++
56 void TGRSIDetectorHit::Clear(Option_t* opt) {
57  ///General clear statement for a TGRSIDetectorHit.
58  fAddress = 0xffffffff; // -1
59  //fPosition.SetXYZ(0,0,1); // unit vector along the beam.
60  fWaveform.clear(); // reset size to zero.
61  fCharge = 0;
62  fKValue =0;
63  fCfd = -1;
64  fTimeStamp = 0;
65  //fDetector = -1;
66  // fSegment = -1;
67  fEnergy = 0.;
68  fBitflags = 0;
69  fPPGStatus = TPPG::kJunk;
70  fCycleTimeStamp = 0;
71  fChannel = nullptr;
72 }
73 ```
74 produces the above image.

76 ### Data Member Documentation
77 [[images/MemberDesc.png]]
78 
79 To document a data member put a C++ comment behind their declaration in the header file using ```///<```:
80 ```c++
81  UInt_t fAddress; ///< address of the the channel in the DAQ.
82  Float_t fCharge; ///< charge collected from the hit
83  Short_t fKValue; ///< integration value.
84  Int_t fCfd; ///< CFD time of the Hit
85  Long64_t fTimeStamp; ///< Timestamp given to hit
86  std::vector<Short_t> fWaveform; ///<
87 ```
88 For transient members ```//!<!``` has to be used:
89 ```c++
90  mutable Double_t fTime; //!<! Calibrated Time of the hit
91 ```
92 ### Latex
93 You can also add LaTeX to function and class descriptions inline by putting the LaTeX code between a pair of \f$ commands. Using the \f[ and \f] commands instead creates a new line with the LaTeX code. Formulas or other latex elements that are not in a math environment can be specified using \f{environment}, where environment is the name of the LaTeX environment, the corresponding end command is \f}.

95 ### Authorship
96 Authorship of a class can be included in the class description at the top of the header file by using the \author command:
97 ```c++
98 /// \author First Lastname <email@some.thing>, home institute
99 ```
100 This is worth doing in all files you make to get credit for your hard work!
